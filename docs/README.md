# 文档模式:让小析只读你指定的那一份文档

小析的知识是**数据包**(离线快照),但很多时候你手上还有一份正在看的文档:
部署手册、需求说明、合同、会议记录。把它们塞进数据包太重了 ——
你真正想说的是「只按这份文档回答我」。

这就是文档模式:**句尾写一个 `@`,这一轮就只读那一份文档,只引用它的原文**。

---

## 文档放哪

放在项目根目录的 `docs/` 里 —— 项目根就是 `xiaoxi.py` 所在的那个目录。

```
xiaoxi.py
docs/
  ├── README.md     ← 你正在看的这份(也是一个可读的文档)
  ├── 部署手册.md
  └── team/
      └── 周报.txt
```

只认 `.md` / `.markdown` / `.txt` 三种。PDF、Word 需要第三方库,小析不装。
目录里最多扫 500 个文件(文档目录不该像代码仓库那样大,超出的不会列出)。

想知道现在有哪些文档:

```bash
python xiaoxi.py --docs          # 命令行
:docs                            # 对话里
:docs 部署手册                    # 直接看某一份的目录
```

## 两种写法

| 写法 | 含义 | 例子 |
|---|---|---|
| `问题@文档名` | 在 `docs/` 里找这份文档 | `怎么回滚@部署手册` |
| `问题@@相对路径` | 按 **`xiaoxi.py` 所在目录**的相对路径取 | `怎么回滚@@docs/部署手册.md` |
| `@文档名` | 只给文档不给问题 | 列出它的章节 |

关于 `@文档名`:

- 可以省扩展名:`@部署手册` 和 `@部署手册.md` 是同一份;
- 大小写不敏感;
- 可以带子目录:`@team/周报`;
- 如果 `docs/` 里有两份同名的(**`部署手册.md`** 和 **`部署手册.txt`**),
  小析**不会替你猜**,会把它俩都列出来,让你用 `@@` 指定。

关于 `@@相对路径`:

- 相对的是 `xiaoxi.py` 所在目录,所以通常以 `docs/` 开头;
- **不许跑出项目目录**:`@@../其他文件.md` 会被拒绝 —— 一个问答程序没有理由
  去读项目之外的任意文件;
- 不接受绝对路径(`D:\notes\x.md`),想读别处的文件,先复制进 `docs/`。

## 回答长什么样

问:`python xiaoxi.py "第一次启动要检查什么@README"`

答(示意):

```
文档:《文档模式:让小析只读你指定的那一份文档》(docs/README.md) · 7 块 / 约 1573 字
这一轮只读这一份,没有查数据包;下面是命中的原文(共 2 段,按相关度排):

1) 章节「文档放哪」 · 第 11–33 行

│ 放在项目根目录的 `docs/` 里 —— 项目根就是 `xiaoxi.py` 所在的那个目录。
│ ……

2) 章节「边界」 · 第 129–142 行

│ 一次只读一份文档;多个 `@` 只有最后一个才是标记……

以上都是原文,我没有改写。

—— 摘自 docs/README.md 的 2 段原文(第 11–33 行、第 129–142 行);原文照录,没有改写。
```

要点:

- **文档行**:哪份文件、几块、多少字 —— 一眼知道读的是哪一份;
- **章节行**:`父节 › 子节` + 行号,改了字之后行号只作定位提示;
- **`│` 起的都是文档原话**:小析自己说的话不会混在引用里;
- **只引用,不改写**:不生成、不补常识、不拿别的数据包来凑;
- 命中的段落按相关度排,最多引 3 段、正文最多 1600 字,超出会说明还有几段没引。

## 排序:为什么先给这一节

一份文档里往往有好几节都沾点边。小析按四路加权排(权重写死、`--trace` 能逐项核对):

| 看什么 | 权重 | 人话 |
|---|---|---|
| 词面证据(BM25) | 0.45 | 这一节里到底提没提你问的词 |
| **标题命中** | 0.20 | 你问的词是不是就在这一节的标题里 |
| **长块优先** | 0.15 | 同样相关时,先给讲得全的那一节(短桩让位) |
| **怎么做(how-to)** | 0.20 | 问法像“怎么/如何/步骤”时,先给步骤型段落 |

两个容易踩的点,这里说明白:

- **“回滚”这一节的正文只写了「见上一节」** —— 标题里有“回滚”就算命中,标题权重会把
  它抬上来,而不是因为正文没提就漏掉;
- **「简版」和「详版」都命中时只引「详版」** —— 简版的文字是详版的前半截时,
  引更全的那一块(同样的证据,长块优先);综合分只差一点时,也先给长的那块。

`--trace` 会把分数拆开:

```
[文档片段] 命中 2 段:
  1) 回滚步骤 · 第 3 块 · 覆盖 1.00 · 0.78 = BM25 0.63×0.45 + 标题 1.00×0.20
      + 长块 0.65×0.15 + 步骤 1.00×0.20(意图 1.0)
  2) 回滚 · 第 2 块 · 覆盖 1.00 · 0.71 = BM25 1.00×0.45 + 标题 1.00×0.20
      + 长块 0.39×0.15 + 步骤 0.00×0.20(意图 1.0)
```

权重只影响**谁先出**,不放宽“有没有命中”:证据不够(查询词覆盖不到、只沾一个词、
标题里也没有)时仍然说没找到。

## 找不到、有歧义、被安全底线挡住

- **没找到这段内容**:如实说没有,并列出这份文档有哪些章节 —— 不猜“你大概想问哪一段”;
- **问题里全是「怎么 / 什么」这类功能词**:会说“没有可检索的实词”,而不是假装文档里没有;
- **文档不存在**:列出最像的几份(`是不是想问:部署手册?`),不会悄悄回退到数据包;
- **内容命中安全红线**:那一段不引用,并说明有几段被挡(读进来的文字也过安全底线);
- **只给文档不给问题**(`@部署手册`):列出章节和行号,相当于看目录。

## 边界

- 一次只读一份文档;多个 `@` 只有**最后一个**是标记(前面的会当成问题的一部分);
  连续 3 个以上 `@` 按普通文字处理,不是标记;
- `@` 前面紧挨英文字母/数字/`.`/`-`/`_`/`+`/`%` 时**不算标记**(邮箱 `a@b.com` 不会被误拆);
  要指定文档,让 `@` 前面是中文、空格或句首;
- 反过来也要注意:问句本身在说 `@` 这个符号时(例如「怎么输入@符号」),
  句尾的 `@符号` 会被当成文档名。小析会明说找不到这份文档,并提示你换个写法;
- **每问都要带 `@文档名`**:小析不会记住上一问读的是哪份文档(文档模式不改对话记忆);
- 只读 `docs/` 与项目目录内的文件,不联网、不落库、不改你的文档;
- 文档模式不记账到“漏问”队列 —— 没命中是文档或问法的事,不是知识缺口;
- 目录里最多扫 500 个文件、最多缓存 16 份文档的切块与索引(按插入顺序淘汰);
- 文档内容变了会重新读(按修改时间 + 大小判断),没变就复用上一次切好的块;
- 行号是**定位提示**不是索引:同一份文档改了字之后,行号以当时的原文为准。
