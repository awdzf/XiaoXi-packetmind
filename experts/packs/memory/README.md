# 记忆数据包(memory)

这是小析**记住你教的知识**的地方。它和其它数据包结构完全一样(`pack.json` 里的条目),
区别只有两点:

1. **条目是你在对话里教的** —— 用 `#` 开头发一句话,确认后就会追加到这里;
2. **角色是 `role: "memory"`** —— 框架知道"这是后来学的",在它和别的数据包都能答时
   会如实说有**歧义**;默认按作者包 > 用户记忆排序,低优先级仍列出,不替你判断谁对。

## 怎么教

在 `python experts/GoChat.py` 的对话里,拿 `#` 开头教一对 **问题~答案**：

```
你 > 小析,量子退相干是什么?
…… 这个我暂时答不上来 —— 你能用一句话告诉我「量子退相干」是什么吗?
你 > # 量子退相干是什么~量子系统的相干性因与环境纠缠而衰减、叠加态看起来变成经典概率的过程
[记忆] 要写入的题:量子退相干是什么
[记忆] 答案:量子系统的相干性因与环境纠缠而衰减……
        拆出的关键词:量子退相干、量子系统、相干性、环境、纠缠、叠加态、经典、概率
        次要关键词(低权重):衰减、过程
是否写入记忆[y/n]: y
[记忆] 已写入 数据包 memory · 条目 user-0001(下次问「量子退相干」就能命中)
```

- `#问题~答案`：题面与答案分开存；旧写法 `#一句话知识` 仍兼容（问题=答案）；
- `#!问题~新答案`：显式修正同一道题（CBR revise），旧答案留在条目的 `revisions` 里；
  同一道题再教一次也会自动更新，不会重复追加；
- 写入/修正前一定会问 `y/n` —— `y` 写，`n` 放弃，什么都不改；
- 关键词是**从题面拆句**拆出来的非常用词，它就是以后命中这条知识的检索键；
- 另外还会存一组**次要关键词**(低权重)：比如"What是'什么'的意思"会补上"意思",
  用来区分同主题的另一条"What是英语单词";
- 记忆包内部有**再命中**:一句"What是什么"如果同时提到两条记忆的关键词,
  会把两条都列出来;紧跟的"那它是什么意思"则会用次要关键词命中"意思"那条,
  不会一直重复上一次的答案;
- 条目里的 `raw` 保存你当时输入的整行(`# ……`),`#?` 回放的就是它。

## 看教过的知识(`#?`)

在对话里输入 `#?`,它会把教过的知识**按你当时的原话**逐行列出来(不做摘要、不改写):

```text
你 > #?
我现在记着 2 条你教的知识(下面是你当时的原话):

# 量子退相干是量子系统的相干性因与环境纠缠而衰减的过程。
# 香蕉是黄色的水果。

要忘掉哪条:用「#-<那句话里的一小段>」;只看一部分:用「#?<关键词>」。
```

`#? 量子` 只看匹配的那几条;`:memory` / `:taught` 是同一个指令的别名。

## 忘掉一条(`#-`)

```text
你 > #- 量子退相干
[记忆] 找到 1 条对得上的:
  # 量子退相干是量子系统的相干性因与环境纠缠而衰减的过程。
确认忘掉这 1 条?[y/n]: y
[记忆] 已忘掉 1 条。
[记忆] 现在还剩 1 条你教的知识。
```

- 按**原话片段 / 关键词 / 条目 id**(如 `user-0001`)找;先列出来,确认后才删;
- 找不到就**什么都不删**,并告诉你现在还有几条;
- 只写 `#-`（后面空着)不会"全忘掉",只会提示用法并列出现有的条目;
- 删掉的 id 不会被下一条复用(包里用 `_next_user_id` 记账)。

## 冲突(歧义)怎么处理

如果同一个问题,记忆数据包和别的数据包**都能答**,默认按
`冲突优先级 = author > memory` 排序:作者包在前,用户记忆仍列出来并注明
“低优先级”。它不会静默丢掉你教的知识,也不会假装两边一样可信:

```text
[歧义] 你教我的记忆和 数据包 physics 各给了一套说法,我没法判断谁对;
       两份原句都原样列在上面,请你核对。
低优先级（author > memory），仍列出供你判断
```

判断"谁对"需要领域知识,而它只做检索 —— 所以它把冲突摆出来,把判断留给你。
想改顺序用 `:priority memory author`,只留高的用 `config.json` 的
`trust.conflict_policy = "strict"`;想把你教的某条标成高置信,用
`:trust memory/user-0001`。

## 它也可以当"父包"(再命中)

记忆包能参与包关系(和别的数据包完全一样):

```json
// memory/pack.json 的 expert 段
"contains": ["apple"]        // 记忆包包含 apple

// 或者在被包含的包里写
"contained_by": ["memory"]   // apple 被记忆包包含
```

这样命中 `apple` 时,反向关键词可能把 `memory` 也带进来(再命中),
回答会说明「A 有 数据包 apple 中的性质,同时也有 数据包 memory 中的性质」。
`rehit_rounds` 默认 1;想关掉用 `--rehit 0` 或 `:rehit 0`。

## 文件说明

```
memory/
├── README.md      ← 这份说明
└── pack.json      ← ★ 用户教的知识都在 entries 里(可手改/可删)
```

也可以放 `kb.json` / `word_vectors.json` 覆盖事实库与词表(一般用不到)。

## 体检

```bash
python experts/core/run.py --pack experts/packs/memory --health
```

空记忆是**正常状态**(还没教过它东西),不是坏包。
